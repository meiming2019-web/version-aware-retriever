# M1.3d: Development-only BM25 baseline

This is real lexical retrieval output, **unscored**. No Recall, MRR,
wrong-version rate or UFPR was computed on drafts. Annotation statuses are
unchanged. This is neither a completed RAG system nor a validated version-aware
method. No pilot judgments or held-out queries were opened or used for ranking.

## Fixed method and input boundary

The configuration was fixed before inspecting development rankings.
Tokenize by casefold then Unicode `r"\w+"`: underscores remain, punctuation
(including dots) separates tokens. `model_dump` stays one token; `TypeError`
becomes `typeerror`; `BaseModel.model_dump` becomes `basemodel, model_dump`.
No stemming, stop words, synonyms or rewriting. Sorted distinct query terms
contribute once each.

With N documents, document frequency df (not occurrence count), token frequency
tf, token length dl and mean length avgdl:

```text
idf(t) = ln(1 + (N - df(t) + 0.5)/(df(t) + 0.5))
score = sum_unique_query_terms idf(t)*tf(t,d)*(1.2+1)
        / (tf(t,d) + 1.2*(1-0.75+0.75*dl/avgdl))
```

Absent terms are skipped. Empty/all-token-empty corpora return no hits.
Rank by descending unrounded score, then ascending evidence ID for exact ties.
Only positive scores are returned; no padding. Optional search k is None
(full ranking) or a nonnegative integer (zero returns none); booleans are rejected.

`BM25Index(tuple[Document, ...]).search(text, k=None)` returns immutable SearchHit
records. Document exposes only evidence_id, ecosystem_id and content. Only
content is tokenized; metadata is never appended. Query types contain only the
six public fields. Structured versions and kind are traceability, not ranking
features. The index scores all supplied documents, without ecosystem or version
filtering; the batch checks that query ecosystems exist in the supplied corpus.
Version numbers inside query text remain ordinary lexical tokens.

The public JSON is a mechanical projection of the eight existing retriever_input
objects. Projection parses authoring JSON but never accesses curation. The runner
reads only public JSON and the evidence artifact, projecting the latter immediately
to the three document fields. It does not load BenchmarkQuery or gold judgments.

## Reproduce

From the repository root:

```text
.venv/bin/python -m version_aware_retriever.acquisition verify
.venv/bin/python -m version_aware_retriever.extraction verify
.venv/bin/python -m version_aware_retriever.lexical --queries data/pydantic/benchmark/queries.dev.input.json --evidence data/pydantic/extraction/derived/evidence.json --output data/pydantic/runs/bm25.dev.unscored.json
```

The first two commands reuse offline integrity checks; the retrieval CLI itself
does not reconstruct extraction or read its recipe. No extraction build is run.
Batch depth is **34**: full positive-scoring ranking up to corpus size for all
eight queries. The display below truncates to five only.

The envelope contains RankedResult-shaped results and aligned numeric scores,
input artifact hashes, fixed configuration and an explicit retrieval-input
snapshot ID. Snapshot identity hashes projected document/query inputs;
run identity hashes that snapshot and configuration. Neither uses timestamps,
local paths or labels. Full evidence artifact hashes are recorded for provenance
but are not ranking features or run-identity inputs. Unchanged output bytes
are not rewritten. This is not a RankedRun bound to an invented benchmark revision:
formal evaluation will require explicit binding to a compatible approved Benchmark.

## Synthetic arithmetic

For D1="alpha alpha", D2="alpha beta", D3="gamma delta", avgdl=2,
df(alpha)=2, idf=ln(1.6). Query "alpha" returns:

- D1: (4.4/3.2) × ln(1.6) = **0.6462549902128863**.
- D2: ln(1.6) = **0.4700036292457355**.
- D3: zero, omitted.

Tests compare independently calculated arithmetic, not expected values derived
by invoking the scorer. These are test results, not retrieval performance.

## Validation and limits

Synthetic tests cover arithmetic, length normalization, saturation, distinct
query terms, Unicode identifiers, empty/OOV inputs, ties, limits, isolation and
repeatability. The real smoke test checks eight results, current evidence IDs,
finite positive scores and repeatable bytes/mtime, not a prescribed ranking.
The guarded runner test permits reads only of synthetic public inputs/output;
no judgment or evaluation files are needed.

No dependencies, labels, corpus content or existing application files changed.
No network access, documentation-example execution, generation, version boosts,
retrieval tuning or formal real-data evaluation was performed.

Executed checks: `.venv/bin/pytest` (**111 passed**), `.venv/bin/ruff check .`,
`.venv/bin/ruff format --check .`, `.venv/bin/mypy --strict` (11 files), and
`git diff --check` all passed. Offline acquisition verify passed for 20 sources
and two licenses; extraction verify passed. Repeated module-CLI runs processed
all eight inputs and preserved run bytes and nanosecond modification time.
Mechanical projection equality was checked without accessing curation fields.
Git status shows only the five expected additions; pre-existing tracked files
remain unchanged. No commits were made.

Initial fixture typing and line-length issues were fixed before the final
checks. An initial cross-tool mtime assertion lost integer precision; the
comparison was rerun entirely in Python and passed with exact nanosecond values.
