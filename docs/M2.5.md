# M2.5: Frozen-candidate cross-encoder reranking

Final development-set retrieval-method experiment. This is a real CPU model run,
not mock evaluation. The narrow hypothesis is improved final ordering of already
retrieved candidates, with source context supplied as text rather than hard tiers.
No model, candidate depth, metadata header or retrieval configuration was tuned
after observing scores. Development-set retrieval iteration now stops.

## Model verification and preparation

Official repository: [BAAI/bge-reranker-v2-m3](https://huggingface.co/BAAI/bge-reranker-v2-m3).
Immutable model/tokenizer revision:
`953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e`.
The official API resolved this revision before inference. Its pinned
`config.json`, `tokenizer_config.json` and `README.md` were inspected.
The card's normal-reranker Transformers example uses
`AutoModelForSequenceClassification`, query/passage pairs, eval/no-grad, and raw
flattened logits. We use that sequence-classification interface, not the card's
separate causal-LLM examples or prompts. Raw logits are not correctness probabilities.

The tokenizer declares `model_max_length=8192`. The model is
`XLMRobertaForSequenceClassification`, one label, 8194 position embeddings,
padding ID 1. XLM-R's nonpadding position IDs start at padding index + 1, leaving
**8192 effective input tokens**, including pair special tokens. These conditions
are checked at load time. The example's `max_length=512` is an example truncation
setting, not the architecture limit; it is not used here.

Fixed configuration: CPU, float32, batch size 4, four Torch threads, SDPA,
deterministic algorithms, evaluation/inference mode, fast tokenizer,
`trust_remote_code=False`, safetensors only. No quantization, training, prompts,
sigmoid normalization, score threshold, applicability filtering or secondary fusion.

Actual environment: Python 3.12.7, Darwin ARM64.

No package was installed or upgraded. The optional `reranker` extra exposes only
the existing compatible Transformers/Torch/Hub requirements without requiring
Sentence Transformers. The six allowlisted model/tokenizer/config/card files
were prepared in the normal external Hugging Face cache. Weights are not in Git.
Preparation initially encountered sandbox network and system urllib CA errors;
official verification succeeded with requests' installed CA bundle and TLS
verification enabled. No TLS verification was disabled. An early offline attempt
correctly rejected the incomplete cache; preparation then completed.

```sh
.venv/bin/python -m version_aware_retriever.reranker prepare
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 .venv/bin/python -m version_aware_retriever.reranker run
```

`run` uses local-files-only even without those environment flags. Missing files
raise an explicit preparation instruction; there is no online or model fallback.
The query/length/scoring adapter is separate from deterministic candidate ordering,
so normal tests do not load weights or access the network.

## Candidate and input boundary

Each of eight public development queries takes exactly the first 20 IDs from the
unchanged frozen RRF run. Source ID/hash, public/evidence hashes, shared input
snapshot, unique query/evidence IDs and aligned finite source scores are checked.
No outside candidate can be introduced. All 20 are returned, ordered by descending
unrounded cross-encoder logit, original RRF rank on exact ties, then ID if still
tied. Original RRF scores are not rerun or combined with logits.

The query is unaltered `query_text`. Each passage is exactly:

```text
[Document snapshot: Pydantic <primary source exact release>]
[Document type: <primary source document_type>]

<unchanged EvidenceUnit.content>
```

The primary SourceManifestEntry supplies project identity, exact document
snapshot release and type; companion content stays in the existing assembled
evidence. No provenance is rewritten. Header policy v1 maps `pypi:pydantic` to
the display name Pydantic, otherwise retaining the ecosystem identifier.
Snapshot is not applicability: a v2 migration passage retains its complete
historical v1 discussion. It is not hard-filtered by snapshot.

Corpus applicability assertions, review status, inspection keys, gold labels,
candidate hints and prior ranks are excluded from input text. All 38 corpus
assertions remain pending and unchanged. Full file hashes bind artifact revisions
but their annotation fields are not model features. Generation reads only the
public query file, evidence file, frozen manifest and RRF file, plus its own
output for byte-equality checks. Model loading reads only the external cache.
No query-specific gold/review/result or held-out files are read by generation.

The real unscored run was frozen before formal scoring. Only then was the M2.2
four-question, 136-pair reviewed pilot loaded for this evaluation. The narrow
adapter adds `--include-cross-encoder`, preserves previous CLI defaults/artifacts,
checks parent lineage and exact top-20 candidate membership, and calls the
unchanged evaluator. The request referred once to a sixth method; there are five
named methods here, and no extra method was added.

Compared with RRF, the cross-encoder improves Recall@3/5 and reduces wrong-version
exposure at three, with unchanged Recall@1/MRR. Wrong-version exposure at five
does **not** improve: the sole reviewed negative remains fourth. Compared with
M2.4, recall and MRR improve but wrong-version@5 regresses from 0 to .05.
Compared with Dense, Recall@3 is lower; this is not universal superiority.
For q:39fa, source evidence slips 3→5 while target evidence improves 6→4, yielding
all three positives through five but only one through three. These are actual
outputs, not hard-coded desired behavior.

The tradeoff improves over RRF on this reviewed pilot at three and in recall at
five, but the reranker is not a version-validity classifier. It has no calibrated
rejection/sufficiency mechanism: q:b503 still returns apparently relevant text
and UFPR remains 1. Raw logits are not comparable in scale to BM25, cosine or RRF.
There was no post-score change to headers, model, labels or rankings.
