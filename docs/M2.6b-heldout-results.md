# M2.6b: Frozen held-out retrieval evaluation

This is the first and final held-out evaluation of the four frozen systems.
**RRF has the highest held-out Recall@3/5 and MRR. Cross-Encoder improves
Recall@1 and removes the one reviewed wrong-version item from the top five, but
regresses on Recall@3/5 and MRR. UFPR is 1 for every method.** No settings or labels
were changed after observing these results.

## Benchmark and explicit review

The user explicitly approved all 16 question decisions and all 544 pair decisions.
The existing sidecar now records each decision separately, with current bindings,
the user-supplied approval attribution (reviewer name not supplied), and no invented
credentials or signatures. This was **AI-assisted batch annotation followed by
explicit human review**, not blind annotation, independent multi-annotator
agreement, runtime verification or expert certification.

- 16 unchanged held-out questions: 5 exact identifier, 7 natural-language migration,
  4 no-supported-evidence; 9 lookups and 7 migration queries.
- 34 fixed searchable evidence units; 12 answerable and 4 corpus-relative
  unanswerable questions; 544 reviewed query–evidence pairs.
- 28 direct valid positive pairs and one reviewed wrong-version hard-negative pair.
- No overlap with the eight development IDs or their validation family. Held-out
  families: required_nullable (4), serialization (4), configuration (3), parsing
  (2), attribute_input (2), schema_output (1). The corpus is shared, not unseen.
- All 38 corpus applicability assertions remain unchanged and pending human
  review. Query-specific approval is not corpus-wide applicability approval.

For **q:16cf × v1-nullable**, the explicit adjudication confirms invalidity only
for transferring old annotation-only omission behavior to target requiredness.
None acceptance remains genuine shared support; not every sentence is invalid.
All other proposed labels and answerability decisions were confirmed unchanged.
The original query and judgment drafts were not rewritten or promoted in place.

Before approval was applied, authored query/draft/evidence hashes, 16 IDs, 544
unique pairs, current evidence IDs and family isolation were verified. A
filename-only check found **no held-out retrieval or result artifacts**. The
reviewed sidecar then passed actual readiness: **16/16 questions, 544/544 pairs,
zero unresolved issues, scoring_permitted=true**. These counts come from the
existing explicit-decision validator, not constants substituted for review.

## Fixed methods and leakage boundary

| Method | Frozen configuration |
|---|---|
| BM25 | M1.3d Unicode word/underscore casefold tokenizer; k1=1.2, b=.75; original positive-log-IDF formula; positive-score returns only; score descending, ID ties |
| Dense | Alibaba-NLP/gte-modernbert-base at `e7f32e3c00f91d699e8c43b53106206bcc72bb22`; published CLS pooling, whitespace preprocessing, CPU float32, batch 4, normalized vectors, original exact cosine, full 34-item ranking |
| RRF | K=60, weights 1/1, one-indexed ranks, full union, descending RRF then evidence-ID ties |
| Cross-Encoder | BAAI/bge-reranker-v2-m3 at `953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e`; CPU float32, batch 4, four threads, SDPA, eval/inference mode; RRF top 20, raw logits descending, original RRF rank ties |

Cross-Encoder uses the same M2.5 header: primary-source exact document snapshot
and document type, then unchanged content; query_text is unchanged. No corpus
applicability, gold, review, curation, rank hints or new prompt is model input.
Snapshot context is not a hard validity filter. There is no score threshold or
rejection. Raw method scores are not comparable on a common scale.

Both neural models used pinned local files only, safetensors and
trust_remote_code=False; no downloads or model substitutions. Actual Python
3.12.7; Torch 2.6.0; Transformers 4.49.0; Sentence Transformers 3.4.1; Hub 0.36.2;
NumPy 2.5.3; Tokenizers 0.21.4; Safetensors 0.8.0. No package changes.

Only orchestration was extended: existing batch wrappers accept the held-out
input/output paths and expected count 16, keeping defaults for eight development
questions. Retrieval math, models, headers, pooling, chunking and configuration
dictionaries are unchanged. M2.4 hard-tiering was **not** run on held-out data;
it remains a development ablation.

Approval and projection are separate from generation. The new public input is
a mechanical projection of exactly query_id, ecosystem_id, query_text, query_kind,
source_version and requested_version. It matches all reviewed texts/contexts and
contains no answerability, category, family, candidates or labels.

The ranking process reads only public inputs, evidence, frozen source metadata,
model/cache files and predecessor/output runs. It never loads held-out judgments,
review decisions or metric artifacts. BM25, Dense, RRF and Cross-Encoder were all
generated and frozen before any output interpretation or formal scoring. Tests
guard input reads with fictional scorers; normal generation has no gold imports.
The batch refuses to start a new experiment if any held-out output already exists.

Before gold was loaded for scoring, all four runs passed: 16 unique query rows,
valid unique evidence IDs, input/snapshot hashes, frozen configurations and return
policies, RRF parent lineage, and exact Cross-Encoder RRF-top-20 set preservation.

## Representative cases selected after scoring

Readable keys are reporting-only joins to current evidence IDs, not model inputs.

### Clear supported result: q:81d6

For the Any implicit-default migration, RRF and Cross-Encoder both put
migration-nullable first and v2-required second: all reviewed positives are in
the first two positions. This is source-supported ordering for this case, not a
claim that the model generated a correct answer.

### Ranking regressions: q:6f21 and q:bb48

For nested-subclass export (q:6f21), migration-subclasses drops **RRF 1 → CE 8**;
v2-nested-subclass moves **12 → 13**. CE's top five are v2-extra,
v2-sequence-filter, v2-dump, v1-sequence-filter and v2-field-validators: no reviewed
direct positives. The relevant candidates were present; this is an ordering
failure, not a candidate-recall explanation.

For configuration placement/continued compatibility (q:bb48), v2-config drops
**2 → 6**, migration-config **5 → 8**, while v1-config improves **12 → 10**.
Again, CE has no direct positives through five despite retaining all three
candidates. These cases explain why improved top-one behavior elsewhere does not
establish migration-evidence coverage. No header/model change was attempted.

### Reviewed wrong-version case: q:16cf

The scoped negative **v1-nullable** ranks **1/1/1/6** in BM25/Dense/RRF/CE.
Cross-Encoder puts migration-nullable first and v2-required second (RRF 2/3).
Its top five then contain v2-dump, v2-field-validators and v2-sequence-filter.
The negative is still in the submitted list at six, not rejected or labeled
invalid by the model. Its invalidity remains the human-reviewed omission-specific
judgment; shared None support is preserved.

### Candidate boundary: q:30e5 and q:ed72

q:30e5 improves migration-from-orm from **11 → 3**, but the separate positive
config-rename unit is outside RRF top 20. q:ed72 puts target v2-extra **2 → 1**,
but source v1-extra at RRF 28 is unavailable. Endpoint-specific positives can be
needed for migration coverage even when the first passage is valid.

### Corpus-relative unanswerable: q:09f1

For the default JSON Schema dialect question, CE returns migration-methods,
v2-dump, v2-sequence-filter, v2-required and v2-nested-filter. These do not establish
the requested dialect under the reviewed corpus judgment. All methods still
return nonempty lists. The other three absence questions likewise receive results.
Ranking scores are not evidence sufficiency or a calibrated answerability test.
UFPR=4/4 motivates future evidence-sufficiency/abstention work, but no rejection
mechanism or threshold was added here. No claim about real Pydantic capability
is inferred from corpus absence.

| Method | Dev Recall@3 / @5 / MRR | Held-out Recall@3 / @5 / MRR |

| BM25 | .611111 / .611111 / 1 | .655556 / .713889 / .736111 |

| Cross-Encoder | .777778 / 1 / 1 | .675000 / .702778 / .815972 |

The development Cross-Encoder Recall@3/5 improvement over RRF **did not transfer**
to held-out data. It still reduces the observed negative exposure, but that is
one different behavior family, not repeated independent evidence of broad
correctness. Development has four exposed questions/three answerable and one
TypeError negative; held-out has 16/12 and one required-nullable negative. Rates
have different denominators and content distributions; this is not a controlled
estimate of a universal performance gap. No comparison triggered tuning.

## Validation, changes and stop condition

Final checks: **206 pytest tests passed**, Ruff lint/format (45 files), strict
mypy (26 files), git diff --check, acquisition verify (20 sources/two licenses),
and extraction verify (no build). Readiness independently reports the complete
review counts above. New tests cover mechanical projection, pending/completed
gates, guarded fictional generation without gold, source/candidate/config checks,
refusal to regenerate, deterministic real scoring and direct agreement with the
existing evaluator. Initial test typing/metadata-read-guard and adapter formatting
issues were fixed; these did not alter retrieval configurations or labels.

Added public eval input, four eval runs, deterministic result, this report,
heldout_retrieval.py, heldout_evaluation.py and focused tests. Updated only the
review sidecar and minimal existing batch/gate wrappers needed to reuse methods
at 16 queries. The earlier pending-gate fixture is now explicitly made pending
in temporary test storage; no real approvals are fabricated by tests. Previous
uncommitted work, development runs/results/labels, query and judgment drafts,
corpus/extraction, metadata, HLD and evaluator formulas are preserved.

Limitations: small single-ecosystem corpus, one negative pair, shared documents,
AI-authored non-blind questions, explicit single human batch review, partial
evidence-unit versus complete-answer coverage, depth-20 candidate loss, no
sufficiency/rejection or generation evaluation. This is defensible measured
engineering evidence, not universal superiority or complete RAG/MVP validation.

**No post-held-out tuning occurred. Retrieval experimentation stops here.** Any
future method change requires a new benchmark revision and must not silently
replace this result. Future evidence sufficiency/abstention and minimal grounded
generation are outside M2.6b. No commit, push, merge or branch switch was performed.
