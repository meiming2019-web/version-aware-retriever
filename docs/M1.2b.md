# Approved source acquisition and freeze

Run from the repository root with the project installed in the development
environment. Acquisition and optional online comparison require network access;
ordinary tests and `verify` do not.

```text
python -m version_aware_retriever.acquisition acquire
python -m version_aware_retriever.acquisition verify
python -m version_aware_retriever.acquisition verify-online
```

An optional `--ca-file /path/to/trusted-ca-bundle` uses a system trust bundle when
the Python installation lacks its CA configuration. TLS verification stays enabled.

`data/pydantic/selection.json` is the reviewed allowlist: 20 content files at two
full Git commits, section boundaries, and primary/companion relationships. Entire
files are archived, but only these sections are eligible for later extraction.
Line locators and inclusion notes remain curation metadata, not executable
extraction rules. No include expansion, example execution, or output generation
occurs. The nine documents and eleven companions remain separate physical sources.

`data/pydantic/frozen/manifest.json` contains SourceManifestEntry-compatible records
with the actual UTC capture time, raw-byte SHA-256, exact document release context,
immutable URLs, tag context, repository paths, license basis, and no-transformation
status. Document release is not a behavioral applicability assertion. No Benchmark,
query, judgment, or EvidenceUnit is constructed for validation.

Source identity is `source:` followed by the lowercase SHA-256 of the UTF-8 encoding
of the compact JSON array `[repository, commit, path]` (no separator whitespace).
Repository is the canonical HTTPS URL without `.git` or trailing slash. Timestamps
do not enter identity. Changing sections changes the selection hash and requires
a separately reviewed freeze, but not the physical source's identity.

Content is stored in `frozen/sources/<commit>/<repository path>`. The original MIT
LICENSE from each commit is retained under `frozen/licenses/<commit>/LICENSE` with
its own timestamp/hash/URL in the manifest. These two administrative artifacts are
not searchable sources and do not increase the 20-source count. Original notices
retain their attribution. The repository-level license is the recorded license
basis; no generated documentation license is substituted.

All fetches must succeed before publication. Bytes are collected in memory, then
written to a temporary sibling directory and verified before renaming the complete
snapshot into place. Failure does not publish a complete archive. A pre-existing
destination is only verified, never repaired or overwritten: missing files,
corruption, missing/duplicate/extra manifest entries, pin/provenance discrepancies,
selection changes, unexpected files, or invalid records cause failure. Successful
reuse preserves the original manifest and capture timestamps exactly. Run one
writer at a time; this small utility is not a concurrent archive manager.

Commit selection metadata, the generated manifest, all retained source bytes,
and both notices together after review. They are deliberately not ignored.
`.gitattributes` disables Git text conversion for upstream bytes and accepts their
original trailing whitespace. Ruff excludes the frozen archive so it cannot lint
or format upstream Python examples; mypy and pytest already target `src`/`tests`.
No `.gitignore` change is needed. Interrupted staging directories, if left by a
process kill, are not complete snapshots and must not be committed.

Offline verification proves agreement with the checked-in selection and recorded
hashes, not independent authenticity if an attacker changes both bytes and hashes.
Optional `verify-online` compares against the pinned official URLs without writes.
No expected hashes were assumed before acquisition. Section truth, extraction
fidelity, compound evidence assembly, and version applicability remain outside
this step. Tests use synthetic bytes and injected fetch functions, not the network.
