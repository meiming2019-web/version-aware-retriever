# M2.4: Positive applicability-aware reranking

This is a deterministic development-only experiment, not a fully validated
version-correctness classifier. It tests whether current source-grounded but
pending corpus metadata is useful as a ranking feature. It does not validate
runtime behavior or complete the HLD/MVP.

## Trust boundaries and frozen policy

- Ranking metadata: all 38 corpus assertions across 34 units remain pending human
  review. No assertions, scopes, evidence identities, or statuses were changed.
- Evaluation gold: the four-question M2.2 pilot has 136 explicitly human-reviewed
  query-specific judgments. These are evaluation inputs only.
- Expressiveness: the corpus schema has positive applicability/transition
  information, not explicit query-relative negative applicability. Missing matches,
  another document version, and deprecation never establish invalidity.

The run was generated and frozen before loading gold/results for this experiment.
The normal ranking path reads only evidence.json, public development queries, and
the pinned frozen RRF run (plus its own output for no-op comparison). A guarded
real-corpus test checks this read boundary. No held-out questions were accessed.
BM25, Dense and RRF were not rerun, re-encoded or tuned.

Policy `positive-exact-applicability-rrf-v1` uses exact selector scheme and literal
value equality; ranges, release lines and unknown selectors do not establish a
match. Invalid selectors are rejected. It does not parse equivalent spellings.

| Query kind | Tier 1 | Tier 2 | Tier 3 | Tier 4 |
|---|---|---|---|---|
| LOOKUP | DIRECT_MATCH | TRANSITION_RELEVANT | UNKNOWN | — |
| MIGRATION | TRANSITION_MATCH | SOURCE_AND_TARGET_MATCH | SOURCE_MATCH / TARGET_MATCH | UNKNOWN |

Lookup behavior assertions match the requested endpoint; transitions may include
it on either side. Migration transitions must match source → target in the same
assertion and direction. Behavior assertions may collectively support both ends.
Any matching positive role takes precedence over unmatched assertions. There is
no negative tier. Matching a scoped assertion does not establish topical relevance
to the question or validate every sentence of the unit.

Ordering is `(tier, original RRF rank)`; within-tier order is preserved exactly.
All 34 IDs per query are retained. Original scores remain unchanged diagnostics,
not a new scalar ranking score. Diagnostics record matched assertion indexes,
claim locators, roles, tiers, original ranks and new positions without gold labels.
The policy and metadata were not changed after scoring.

The q:a7c2 reviewed wrong-version item `v2-validator-errors` remains UNKNOWN:
BM25/Dense/RRF/new ranks are **5/2/2/26**. Its movement is a consequence of
positive tiers moving ahead, not detection of invalidity. It remains in the full
list. Positive `v1-errors` improves 5→2, but `migration-typeerror` falls 1→15.
Thus q:a7c2 reciprocal rank worsens despite reduced top-five wrong-version exposure.

For q:39fa, transition evidence stays first while source/target positives fall
3→13 and 6→15. Unrelated matching transitions outrank relevant endpoint-only
evidence. q:7bd4's positive remains first. q:b503 still returns 34 items despite
being unsupported; positive endpoint metadata is not an answerability test.

These regressions show that coarse positive tiering can override topical order.
The current metadata cannot itself identify query-relative wrong-version items;
the observed top-five improvement does not establish a general validity classifier.
No tuning or new annotations were used to repair this outcome. Four pilot
questions and one reviewed negative pair are insufficient for broad conclusions.

## Verification and HLD checkpoint

- `python -m version_aware_retriever.version_aware` twice: identical stdout and
  bytes, unchanged output mtime; eight queries × 34 unique IDs.
- `python -m version_aware_retriever.pilot_evaluation score --include-version-aware --save`
  twice: identical stdout and bytes, unchanged output mtime. Review gate and
  source-run lineage checks precede scoring; prior CLI defaults are preserved.
- `python -m version_aware_retriever.acquisition verify`: 20 sources/two licenses passed.
- `python -m version_aware_retriever.extraction verify`: passed; no build.
- `pytest`: 179 passed. Synthetic relation tests, stable ties, score preservation,
  selector handling, lineage, determinism and guarded structural smoke included.
- `ruff check .`, `ruff format --check .`, `mypy --strict`: passed (34 formatted
  files; 19 type-checked files). Initial format/test tuple-typing issues were fixed.
- `git diff --check`: passed. Tracked changes are limited to the pilot adapter and
  its tests; protected corpus/recipe/source/query/review and prior run/result
  files remain unchanged against HEAD. No dependencies, network, example
  execution, held-out evaluation, commit or branch operation.

HLD-aligned pieces implemented: sparse baseline, dense baseline, hybrid baseline,
experimental deterministic metadata reranking, retrieval evaluator. Still future:
learned/model-based reranking, context selection, generation, citations,
abstention/rejection policy, held-out evaluation and second-ecosystem validation.
The HLD and end-to-end MVP are not complete. Corpus human review remains pending.
