## Minimal decision contract and gate

No bulk-approval operation is provided. After actual inspection, record each
decision explicitly; there is no automatic expansion of a named group into
approvals. Reviewer names must come from real reviewers, not the assistant.
The loader validates records, not identity/authenticity or whether a person
actually read the cited wording. Semantic source support remains a human duty.

Sidecar keys are exactly `format`, `status`, `bindings`, `question_decisions`,
`pair_decisions`, `unresolved_issues`. Format is `development-pilot-review-v1`.
Keep overall status pending during partial review; reviewed is allowed only with
all decisions. A reviewed overall status alone never opens the gate.

Question decisions require exactly:

- `query_id`, `status: reviewed`, actual `reviewer`, `answerability` (answerable or
  unanswerable), nonblank source-grounded `rationale`;
- `reviewed_all_evidence: true`: explicit whole-corpus inspection, not a default;
- `supporting_evidence`: list of `{evidence_id, locator}`. Answerable decisions
  need at least one reference. Unanswerable decisions may use an empty list:
  absence is a corpus-review conclusion, not a fabricated decisive quotation;
- `unresolved_issues`: explicit list, empty only when none remains for the decision.

Pair decisions require exactly:

- `query_id`, `evidence_id`, `status: reviewed`, actual `reviewer`;
- `action: confirm` with empty `correction`, or `action: correct` with a nonempty
  label patch limited to topical_relevance, version_applicability, evidence_roles,
  hard_negative. No pair-ID/content/status patching;
- nonblank source-grounded `rationale` and nonempty `supporting_locators`, including
  for corrections. Locators are `chars:start:end` in that evidence revision;
  contributions map those spans to source files. They are not original line numbers;
- `issue_resolution`: null where not needed, or explicit reasoning resolving an
  original issue; `unresolved_issues`: list of any remaining material concerns.

All actual decisions refer to the six bound artifact revisions and exact IDs.
Duplicate JSON keys, duplicate/unknown decisions, stale bindings, invalid label
combinations, unauthorized patches and out-of-range locators are rejected.
The complete reviewed matrix must agree with the four explicit answerability
decisions: answerable requires a reviewed valid positive, unanswerable zero.
Reviewed UNKNOWN stays UNKNOWN. The gate requires all 4 + 136 decisions, overall
reviewed status, and no unresolved material issues at any level. Neither passed
tests nor acceptance of these instructions supplies missing decisions.

## Scoring integration and limits

Only after the gate passes is a separate in-memory reviewed pilot constructed
using the existing Benchmark and **all 34 units**. Corpus applicability assertions
and curator notes are unchanged; pair review is not corpus-wide approval.
Revision hashes bind original artifacts and explicit sidecar decisions.
The eventual stdout report includes reviewed pilot queries/judgments, evidence
IDs, source/input bindings, new benchmark-bound runs, and evaluator reports.
It does not overwrite the draft or saved unscored runs.

The adapter checks both saved runs against the exact full eight-query public
projection and 34-document input snapshot, current artifact hashes, complete
unique query IDs, known unique result IDs, and aligned finite scores. It then
selects the four pilot lists **without changing their order or accepted items**.
New run identities include original run ID/hash and pilot benchmark revision.
No rerunning, re-encoding, top-five clipping, corpus reduction, or threshold tuning.

The existing evaluate() supplies Recall@1,3,5, full-submitted-list MRR,
item-weighted wrong-version rate@1,3,5, UFPR, per-query diagnostics and counts.
There is no second formula path. BM25 returns positive lexical scores; dense
returns all defined similarities. Neither has calibrated rejection. Any eventual
UFPR describes these declared return policies, not trained missing-answer detection.

This is four development questions with only **one proposed wrong-version
behavior-change family** (validator TypeError). It does not meet the original
negative-coverage target, establish broad generalization, complete M1, or constitute
held-out evaluation. No held-out questions were read. No real metric values or
synthetic placeholders are reported here.
