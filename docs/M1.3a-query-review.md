## How to review the cards

Topical relevance asks “does this passage address the fact being asked?” Version applicability separately asks “does that fact hold for the requested endpoint or migration role?” A passage can be relevant but describe the opposite endpoint. A v1 passage can also be valid source-side evidence for a migration. Snapshot policy supports exact endpoint proposals; the source wording usually does not name the patch release.

For **each card**, the human reviewer may choose, without any preselection:

- accept the proposed interpretation / 接受所提解释；
- revise the question or interpretation / 修改问题或解释；
- uncertain / needs more review / 不确定，需要进一步审查。

S1 means frozen commit `8822578619bf8d0bb754b1cf7a2a905b50240d01` (1.10.13); S2 means `9f58e785a5f1f2c34437f6e9b6adcd5b969e0df4` (2.5.3). Paths below resolve under `data/pydantic/frozen/sources/<commit>/`; line spans are inclusive original-file coordinates. Excerpts normalize line wrapping only.

## Card 1 — exact lookup, q:a7c2

**Question:** In Pydantic 1.10.13, if my @validator raises TypeError, does the caller receive TypeError or ValidationError?

中文：用户问的是旧版本中，校验函数抛出的类型错误最终以什么异常到达调用方。请求版本：**1.10.13**。

- **v1-errors** — `evidence:d7267def0efc3affe89aebfe80b279bd6910209fc2db679c5c98f16571254127`. S1 `docs/usage/models.md` L177–179: “raise `ValueError`, `TypeError` or `AssertionError`” and “caught and used to populate `ValidationError`.” 中文：主题直接相关；按端点快照政策，这是旧版本包装异常的候选支持证据。
- **v2-validator-errors** — `evidence:a9c73c27473d19d0472e7ebb2f5a313950f5cc6ce9c5b3100f9aff1a5ece31ff`. S2 `docs/concepts/validators.md` L472: “Any other errors (including `TypeError`) are bubbled up and not wrapped in a `ValidationError`.” 中文：主题同样直接相关，但描述新版本的相反行为。结合明确的迁移说明，它是这个旧版本查询的候选错版本证据，不是因为文件较新就判错。
- **migration-typeerror** — `evidence:4bd23223de4ab66136b4944b2145e5c28ddbbc025f58c337cac6bf182c323bc5`. S2 `docs/migration.md` L317: “Previously, when raising a `TypeError` within a validator function, that error would be wrapped into a `ValidationError`”. 中文：文档快照是 v2，句子却明确描述历史行为，因此能支持 v1 问题；不能把整份 v2 文档都排除。

人工需决定：问题是否明确限定校验函数内部的 TypeError；历史文本到所选端点的映射是否可接受；候选负例是否只针对本查询。状态：pending。

## Card 2 — changed behavior, q:39fa

**Question:** After upgrading from Pydantic 1.10.13 to 2.5.3, calling a function with the wrong signature inside my field validator raises TypeError directly instead of wrapping it in ValidationError. What changed?

中文：用户在字段校验器内以错误的函数签名调用函数，导致 TypeError；升级后该异常直接传出，不再包装为 ValidationError，想理解原因。方向：**1.10.13 → 2.5.3**。条件现在已写入问题，不再依赖隐藏解释，也不推广到所有编程错误。

- **migration-typeerror** — `evidence:4bd23223de4ab66136b4944b2145e5c28ddbbc025f58c337cac6bf182c323bc5`. S2 `docs/migration.md` L319–323: “calling a function with the wrong signature might produce a user-facing `ValidationError`”; “when a `TypeError` is raised in a validator, it is no longer converted into a `ValidationError`”. 中文：同时说明旧现象与新规则，是直接的迁移候选。
- **v1-errors** — `evidence:d7267def0efc3affe89aebfe80b279bd6910209fc2db679c5c98f16571254127`. S1 `docs/usage/models.md` L177–179: “`TypeError`” among errors “caught and used to populate `ValidationError`.” 中文：提供迁移前行为，不能当成这个迁移问题的错版本负例。
- **v2-validator-errors** — `evidence:a9c73c27473d19d0472e7ebb2f5a313950f5cc6ce9c5b3100f9aff1a5ece31ff`. S2 `docs/concepts/validators.md` L472: “including `TypeError`” and “not wrapped in a `ValidationError`.” 中文：提供迁移后的行为。它与旧文本不同并不代表两者只能留一个；两者分别支持迁移的两端。

人工需决定：明确后的错误函数签名场景是否自然、是否忠实于引文；不得扩大到所有编程错误。此次仅作草稿措辞澄清，不代表人工批准。主题相关性不等于版本无效性。状态：pending。

中文：用户想知道启用 Python 优化参数后，写在校验器里的 assert 是否仍有效。请求版本：**2.5.3**；v1 对照用于说明这是稳定行为，不是升级引入的变化。

- **v2-field-validators** — `evidence:5ed599d618c2a175889d935bc3f49c783f312ea2c927b24eadc9e72166b05bb6`. S2 `docs/concepts/validators.md` L380–383: “If you make use of `assert` statements” and “disables `assert` statements”. 中文：直接支持目标版本中 assert 检查被禁用。条件不能丢掉；这不是说所有校验器都失效。
- **v1-validators** — `evidence:de3bf67621ae0433616b3b88bbad1052768664fea091db62c16a5f92c19fd83b`. S1 `docs/usage/validators.md` L19–21 contains the same conditional wording and “disables `assert` statements”. 中文：旧端点也明确记录相同规则。主题相关，可作为稳定行为对照；不能仅因版本不同标为无效。它单独是否足以支持目标端点，仍需结合目标证据和政策审查。

人工需决定：是否把问题严格理解为 assert 检查而非整个模型的所有保护；旧文本在此是背景/稳定对照，已移入 illustrative_background_evidence；v2-field-validators 留在直接支持列表。不强行制造负例，也不赋予 gold 标签。状态：pending。
