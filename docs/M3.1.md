## Final MVP architecture

```text
Query → BM25 + Dense → RRF → Top 5 evidence → Grounded Generator
                                         → SUPPORTED + citations
                                           OR INSUFFICIENT_EVIDENCE
```

The later frozen M2 decision supersedes exploratory HLD filtering/reranking and
context-selection ideas: no additional filtering, reranking or complementary
selection is performed. RRF has the strongest held-out Recall@3 (0.7833),
Recall@5 (0.8111) and MRR (0.8333). Cross-Encoder reduced observed wrong-version
exposure, but its development Recall advantage did not transfer to held-out;
it and M2.4 remain ablations. These are retrieval metrics, not end-to-end answer
accuracy.

## Grounding design

The module reuses BM25Index, SentenceEncoder/embedding_pass, VectorIndex and fuse.
Full lexical/dense rankings use unchanged configurations; only the first five
RRF results enter synthesis, in original order. Arbitrary nonempty query text is
unchanged, including any explicitly stated versions. No inferred version parser
or default requested version is introduced. Local pinned dense model files are
required; retrieval cannot download. No new vector cache is written.

Two pinned frozen artifact files are the normal path's only repository inputs:
evidence.json and manifest.json. SHA-256 checks fail closed on revision changes.
Context is JSON with query and five delimited evidence objects: evidence ID,
ecosystem, section, contribution provenance, and unchanged content. Provenance
includes exact snapshot/commit, document type, title/path, physical source lines
and half-open assembled character spans, including companion examples. JSON
escaping is reversible; document content cannot create message roles or sibling
fields. Only the fixed instruction occupies the system role. All retrieved text
is untrusted data. This structural boundary is not a proof of model resistance
to prompt injection.

Corpus applicability assertions, curation, inspection notes, gold, review sidecars,
categories, families, and results are not projected into context. All 38 corpus
assertions remain pending human review. The module imports no scoring or review
adapter. Existing query-specific human approval is not corpus-level approval.

GroundedAnswer is immutable and runtime-validated. SUPPORTED requires nonblank
answer/support_summary and unique citations drawn only from supplied Top 5.
INSUFFICIENT_EVIDENCE requires an exactly empty answer and empty citations;
support_summary explains the missing essential support. The prompt requires
inline evidence-ID citations for technical conclusions and preserves historical,
version-transfer and deprecation qualifications. Local validation enforces schema
and ID membership, not entailment, claim coverage or version validity. Malformed
output, refusal and transport failure are errors, not fabricated abstentions.

## Provider and commands

One OpenAI Responses REST adapter uses an explicitly supplied --model (or
OPENAI_MODEL) and OPENAI_API_KEY from the environment. No provider/model fallback,
automatic retry, temperature experiment, tools, memory or dependency addition.
Requests set store=false and max_output_tokens=4096 with a 180-second transport
timeout (originally 60 seconds; diagnostic-only change described below).
Only bounded, sanitized allowlisted HTTP diagnostic fields or transport exception
types are reported; no keys, request headers or complete provider bodies are logged.
The adapter follows the official [Structured Outputs guide](https://developers.openai.com/api/docs/guides/structured-outputs)
for text.format JSON Schema and separately handles refusals/incomplete responses.

```sh
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 .venv/bin/python -m version_aware_retriever.grounded_answer --query 'In Pydantic 1.10.13, will model.dict(exclude_none=True) omit a field explicitly set to None?' --context-only
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 .venv/bin/python -m version_aware_retriever.grounded_answer --query 'In Pydantic 1.10.13, will model.dict(exclude_none=True) omit a field explicitly set to None?' --model "$OPENAI_MODEL"
```

Set credentials through the environment, never command-line key arguments. Normal
pytest uses only fictional data, fake encoders/generators and mock HTTP responses.

## Limitations

Small single-ecosystem corpus and small reviewed benchmark; one explicit human
batch review; only one reviewed held-out wrong-version hard negative. Shared
documents and AI-authored questions limit generalization. Retrieval UFPR=1 because
ranking returns evidence even for corpus-relative absence. Generation abstention
is not calibrated at population scale. Top 5 may omit essential support. Valid
citation IDs need not entail a claim, and the model may misinterpret evidence.
No runtime documentation examples are executed. No production readiness or
universal superiority claim. No post-generation tuning is permitted.

## Diagnostic-only revision and authorized retry: stopped

No successful generation output was observed before this change. On explicit
user authorization, the existing urllib adapter gained separate HTTP, timeout,
connection and malformed-JSON diagnostics, and its fixed transport timeout was
increased from 60 to **180 seconds**. No SDK/provider abstraction was introduced.
The official [API error guide](https://developers.openai.com/api/docs/guides/error-codes)
informed the HTTP-versus-connection distinction; its retry suggestions were not
adopted because this experiment forbids automatic retries.

HTTP diagnostics read at most 8193 bytes, omit oversized/non-JSON bodies, and
allowlist only status, x-request-id, error type/code/param/message. Strings are
bounded to 300 characters, control characters normalized, known credentials and
echoed input strings redacted, and obvious bearer/API-key/token patterns removed.
Network errors expose only exception type, never an arbitrary reason string.
Malformed successful response JSON is reported separately. No automatic retry.

The request construction block was compared with the pre-change source and is
unchanged, including model selection, roles, system instruction, context,
store=false, max_output_tokens=4096 and strict text.format schema. Reasoning

## TLS diagnosis, safe process-scoped repair and completed qualitative check

Root cause: **A — missing/broken Python CA bundle**. Project Python is 3.12.7,
using OpenSSL 3.0.15. Its default CA file/directory did not exist; resolved
cafile/capath were both None, and create_default_context loaded **zero CAs**.
SSL_CERT_FILE, SSL_CERT_DIR, REQUESTS_CA_BUNDLE and CURL_CA_BUNDLE were unset.
An existing certifi **2026.7.22** bundle was present and loaded **121 CAs**.
No installation or upgrade was required.

HTTP_PROXY and HTTPS_PROXY were set to the same local HTTP proxy (credentials
absent); ALL_PROXY was unset, NO_PROXY was set and did not bypass api.openai.com.
urllib discovered that proxy. Global Git http.proxy/https.proxy pointed to the
same local proxy; no Git configuration was modified. System curl through this
environment returned HTTP 401, while default urllib failed with verification
code 20: unable to get local issuer certificate.

With the existing certifi public roots, a verified connection through the same
proxy showed subject **api.openai.com**, issuer **Google Trust Services WE1**.
This is evidence of a normal publicly trusted chain, not a need to import a
local interception CA. No proxy was removed, and no certificates were imported.

The narrow repair was to set **SSL_CERT_FILE to certifi.where() only in the
diagnostic/generation process environment**. No persistent system, shell, Git or
application changes were made; a future fresh shell still needs this setting
unless its Python installation trust store is repaired separately. Machine-local
paths and CA certificates are deliberately not recorded in repository files.
For an ordinary future CLI invocation, the portable setup is:

```sh
export SSL_CERT_FILE="$(.venv/bin/python -c 'import certifi; print(certifi.where())')"
```

This is not authorization to rerun the frozen qualitative experiment. Verification
remained CERT_REQUIRED with check_hostname=True. Repeated unauthenticated curl
and **normal default-context urllib** requests to /v1/models both returned
**HTTP 401**, proving TLS completed before generation resumed. No Authorization
or API key was sent for these diagnostics. No unverified context or TLS bypass.

Then, and only then, q:90b7 was attempted once with the unchanged adapter. It
succeeded and was frozen before q:81d6 ran once. That output was frozen before
q:09f1 ran once. All three passed the existing answer validator. Exact configured
model: **gpt-5.6-sol**; reasoning omitted (documented default medium); timeout
180 seconds; store=false; max_output_tokens=4096; unchanged strict Structured
Outputs schema, prompt and RRF Top-5 policy. No alias, retry, fallback or tuning.
Only generated output_text is exposed by this adapter; a provider-reported model
echo, usage and effective reasoning telemetry are not retained or claimed.
