# M2.3: Fixed reciprocal-rank-fusion development experiment

This tests HLD §13's fusion idea and §24's controlled sparse/dense/hybrid
comparison, using only the already frozen rankings. The narrow question is
whether one label-independent fusion combines complementary lexical/semantic
ordering—not whether hybrid is universally better. **No version awareness** is
introduced. All parameters below were fixed before hybrid evaluation; no labels
or parameters were changed in response to these results.

## Fixed method and input boundary

For each evidence ID, add `1/(60+rank)` from each source that returned it.
Ranks are one-indexed; **K=60**, **BM25 weight=1.0**, **Dense weight=1.0**.
Missing items contribute zero. Return the full union, ordered by descending
unrounded sum and ascending evidence ID for exact ties. No cutoff, threshold,
source bonus, version rule, score transformation or learned component is used.
An RRF score is not confidence, answerability probability, or applicability.

BM25 scores and cosine similarities have different scales, so they are neither
normalized nor added. Their finite values/alignment are validated, then discarded
from fusion; only ID order reaches `fuse()`. Synthetic changes to score values
leave the fused ranking/scores unchanged (but change provenance identity).

The normal hybrid command reads exactly these four inputs:

- `data/pydantic/benchmark/queries.dev.input.json`;
- `data/pydantic/extraction/derived/evidence.json`, immediately projected to
  evidence_id, ecosystem_id, content for snapshot verification;
- `data/pydantic/runs/bm25.dev.unscored.json`;
- `data/pydantic/runs/dense.dev.unscored.json`.

It may read its own output for a no-op rewrite check. It never reads judgments,
review decisions, evaluation results or held-out questions. It imports only
retrieval input/projection helpers from lexical.py, not BM25 scoring functions;
it does not import Dense encoding or the pilot evaluator. Text is used to verify
comparability, not to run retrieval. No source ranking is regenerated.

Both sources must match the current public-input/evidence byte hashes and the
projected snapshot, including all eight queries and 34 unique evidence IDs/texts.
Source run IDs and full bytes are pinned in the module to the following already
frozen artifacts, independently of labels. A changed file is rejected, not repaired.
Each query must occur once; result evidence must be known/unique; declared depths
and aligned finite diagnostics must be valid. Both sources are validated before
any fusion. Different depths and empty source lists are supported; the real Dense
source returns all 34, so all eight real hybrid lists also contain 34.

## Four-question metrics

Recall/MRR are macro means over three answerable questions. Wrong-version rate
counts directly relevant version-invalid returns over all returned items at each
cutoff across four questions. UFPR has one unanswerable question as denominator.
Decimals are rounded here only; JSON retains evaluator precision.

### Wrong-version exposure and rejection

The only approved hard-negative pair is q:a7c2 × v2-validator-errors. Its positions
are BM25 **5**, Dense **2**, Hybrid **2**. Consequently, Hybrid's wrong-version
counts at 1/3/5 are **0/1/1**, and its item-weighted rates are 0, 1/12, 1/20.
The same passage is valid target-side support for q:39fa. No other pilot question
has a wrong-version return through five; UNKNOWN is not treated as invalid.

BM25 returns positive lexical scores; Dense returns all defined similarities;
Hybrid returns their union. All lack a calibrated rejection mechanism. For
q:b503 each returns a nonempty list (32/34/34 respectively), so all have UFPR=1/1.
This measures declared acceptance policies, not trained missing-answer detection
or generated hallucinations. No threshold was added to improve UFPR.
