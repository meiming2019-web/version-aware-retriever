# M1.3c: Minimal retrieval evaluator

`evaluate(benchmark: Benchmark, run: RankedRun) -> EvaluationReport` lives in
`version_aware_retriever.evaluation`. It accepts existing in-memory contracts,
not JSON files or internal retrieval candidates. Only accepted result lists are
scored. There is no draft bypass, label inference, CLI, or real-data loader.

Existing records validate at construction. At scoring, the function rechecks
GoldJudgment validation, Benchmark coverage/review/answerability requirements,
RankedRun and RankedResult uniqueness, then `run.validate_against(benchmark)`.
Malformed inputs raise the existing `ContractError`. A poor but structurally
valid run, including wrong-version returns or empty lists, remains scoreable.
The function does not mutate inputs or change review statuses.

## Metrics

Let A and U be answerable and unanswerable queries. G(q) contains reviewed or
adjudicated judgments with relevance 2 and valid applicability. R(q) is the full
ordered accepted list; R_K(q) is its first min(K, length) entries. K is fixed to
1, 3, 5.

- **Recall@K:** for each q in A, `|set(R_K(q)) intersect G(q)| / |G(q)|`.
  The aggregate is the arithmetic mean over A, not Hit@K. U is excluded.
- **MRR:** average over A of the reciprocal of the first positive's rank in
  the **complete** submitted list, or zero when absent. This is not MRR@5.
- **Wrong-version rate@K:** count relevance-2, invalid items in R_K across
  **all queries**, divided by the number of actually returned items at K.
  Item-weighted, not a mean of query rates or a K-times-query denominator.
  The `hard_negative` hint is not required to count a labeled mismatch.
- **UFPR:** fraction of U with any accepted result, even unrelated or unknown
  evidence. It measures retrieval rejection, not generated-answer correctness.

Unknown applicability earns neither positive nor wrong-version credit. Counts
of unknown returned items at every cutoff include all relevance grades and all
queries. Unrelated invalid items do not count as wrong-version hits.

No A means Recall and MRR are `None`. No U means UFPR is `None`. No returned
items at a cutoff means its wrong-version rate is `None`. With A present but
empty results, recall and MRR are zero; with U present and all abstentions,
UFPR is zero. No NaN or rounding is introduced. Contracts forbid an entirely
empty benchmark, but allow either query class to be absent.

## Inspecting the report

Frozen dataclasses and tuples contain revision/run IDs, fixed cutoffs, total/A/U
query counts, accepted item count, empty-query-result count, and UFPR numerator.
`at_cutoffs` contains aggregate recall, wrong-version rate, its numerator and
denominator, and unknown counts. `queries` follows benchmark query order and
contains gold/accepted counts, cutoff hits/recall/counts, first-positive rank,
reciprocal rank, and an unanswerable false-positive indicator. Recall and
reciprocal rank are None for U; the false-positive indicator is None for A.
Cutoff tuples follow (1, 3, 5). Identical inputs produce identical reports.

## Hand-worked fictional example

All fixtures are test-only. Synthetic reviewed/adjudicated statuses solely
exercise contracts; they are not human sign-offs on real project data.

| Query | Gold positives | Accepted list |
|---|---|---|
| A | E1, E2 | E3, E1 |
| B | E4 | E4 |
| U | none | empty |

E3 is directly relevant but version-invalid for A. Complete synthetic pair
judgments are provided, including other unrelated/unknown units.

At K=3, A recall is 1/2; B recall is 1. Mean recall is `(0.5 + 1)/2 = 0.75`.
MRR is `(1/2 + 1)/2 = 0.75`. Wrong-version rate is `1/(2+1) = 1/3`, not
the mean of 1/2 and zero. UFPR is 0/1 = 0. The test asserts these independently
hand-calculated values against the computed report. At K=1 recall is 0.5 and
wrong-version rate is 0.5. Full precision is retained, with approximate equality
only where a test compares a fractional floating-point value.

## Checks and limits

Run from the repository root:

```text
.venv/bin/pytest
.venv/bin/ruff check .
.venv/bin/ruff format --check .
.venv/bin/mypy --strict
git diff --check
.venv/bin/python -m version_aware_retriever.acquisition verify
.venv/bin/python -m version_aware_retriever.extraction verify
```

Formal scoring requires valid reviewed benchmark inputs. The real **136 pilot
judgments remain draft/pending**; they were not loaded for this implementation.
No real benchmark scores were produced. Synthetic arithmetic results are not
retrieval performance, and accurate calculation does not establish gold-label
correctness. No retrieval, metrics beyond the four specified, generation,
network access, documentation-example execution or extraction build is included.
